# 快团团素材生成器 V1 需求文档示例

| 项目 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 编写日期 | 2026-10-11 |
| 文档状态 | 评审稿示例，尚未开发 |
| 使用对象 | 所有者及内部团队 |
| 产品形态 | 在电脑浏览器中使用的单页工具 |
| 核心用途 | 根据一批商品资料和图片，批量生成商品海报 |

> 本文基于已确认的简版范围。具体的数量、文件大小和版式默认值属于本示例的设计建议，不代表已通过真实素材测试。文档确认后，再编写实施方案。

## 1. 要解决的问题

团队的商品资料放在 Excel 或飞书表格中，商品图片保存在电脑上。逐个商品填写信息、上传图片、调整版式和下载，会产生重复操作，也容易配错图片或价格。

第一版让用户一次粘贴商品资料、一次选择商品图片、上传一个统一二维码，即可生成这一批商品的海报。每个商品对应一张图片，用户检查预览后打包下载。

### 1.1 产品目标

- 减少逐个商品重复录入和下载的操作。
- 商品名称、团购价和商品图片对应准确。
- 所有海报使用统一版式和尺寸。
- 用户能知道哪些资料有问题，以及应如何修正。

### 1.2 成功标准

一批有效商品资料生成同样数量的海报；海报中的名称、价格、主图与各行资料一致；整批二维码一致；ZIP 中无漏图、重名覆盖或额外商品；导出的二维码能够实际识别。

## 2. 第一版范围

### 2.1 必须提供

| 编号 | 功能 | 具体范围 |
|---|---|---|
| F01 | 批量录入 | 从 Excel／飞书复制三列资料，粘贴到文本框 |
| F02 | 批量选择图片 | 一次选择多张本地商品图片，按文件名匹配 |
| F03 | 统一二维码 | 上传一个二维码图片，本批次所有商品共用 |
| F04 | 资料检查 | 检查列数、名称、价格、图片匹配及文件有效性 |
| F05 | 海报预览 | 一个固定模板，每个商品一张预览图 |
| F06 | 批量导出 | 所有检查通过后，将 PNG 海报打包为一个 ZIP |

### 2.2 第一版不提供

- Excel 文件上传和解析、CSV 文件上传、直接读取飞书。
- 自动获取快团团商品资料、自动识图匹配或生成二维码。
- 多模板、自由拖拽、颜色选择、字体选择和尺寸选择。
- 原价、优惠金额、卖点、副标题、推荐语、发货信息及团长名称。
- 每个商品单独的二维码、一个商品多张海报。
- 单独的商品编辑表单；修改统一在原粘贴文本中进行。
- 账号、权限管理、在线协作、历史记录和草稿保存。
- AI 文案、AI 生图、自动发送、自动发布。
- 单张下载、勾选部分商品导出、导出 PDF 或 JPG。

## 3. 使用场景与完整流程

### 3.1 典型场景

团队准备了一批商品的名称、团购价和主图文件名，需要生成用于微信群或朋友圈的商品海报。所有海报使用同一个二维码。

### 3.2 操作流程

1. 在 Excel 或飞书表格中，将资料按“商品名称、团购价、图片文件名”三列排列。
2. 复制连续的三列单元格，粘贴到工具的商品资料文本框。
3. 点击“选择商品图片”，一次选择这一批商品所需的图片。
4. 点击“选择统一二维码”，选择一个二维码图片。
5. 点击“生成预览”，工具检查资料、匹配图片并生成海报。
6. 如果发现问题，在文本框中修正资料，或重新选择图片，再次生成预览。
7. 确认全部预览后，点击“下载全部海报 ZIP”。
8. 解压 ZIP，并检查商品信息与二维码，再自行使用海报。

整个流程只读取原始表格和本地文件，不修改原表格、图片或二维码。

## 4. 商品资料输入规则

### 4.1 固定三列

| 顺序 | 字段 | 必填 | 规则 |
|---|---|---|---|
| 第一列 | 商品名称 | 是 | 去除单元格首尾空白后不得为空；建议上限 36 个字符 |
| 第二列 | 团购价 | 是 | 必须为大于 0、最多两位小数的十进制金额 |
| 第三列 | 图片文件名 | 是 | 必须包含扩展名，与所选图片的完整文件名一致 |

示意表如下，实际使用时从 Excel／飞书的原始单元格复制：

| 商品名称 | 团购价 | 图片文件名 |
|---|---:|---|
| 冰糖心苹果 5斤装 | 19.90 | apple.jpg |
| 鲜牛奶 250ml×12盒 | 39.9 | milk.png |
| 抽纸 20包 | 29 | tissue.webp |

### 4.2 文本解析

- 一行表示一个商品，列之间使用表格复制产生的制表符分隔。
- 接受 Windows 和 macOS 常见换行形式。
- 忽略整行为空的行；非空行中缺失的单元格不能忽略。
- 每一非空数据行必须恰好有三列，不将多出来的列静默丢弃。
- 去除每个单元格首尾的空白，不改变名称内部空格。
- 第一条非空行可带表头；仅当三列依次为“商品名称、团购价、图片文件名”时识别并忽略。
- 仅有表头或空白时，提示“请粘贴至少一条商品资料”。
- 不接受 Markdown 表格、用逗号或空格代替制表符的文本、合并单元格或单元格内部换行；格式不符合时说明应从连续三列单元格复制。
- 不自动补价格、猜列顺序或合并商品。
- 允许商品同名，允许不同商品引用同一张图片；每一有效数据行仍生成一张海报。
- 错误提示使用粘贴文本的实际行号，包括表头和空行，便于定位。

### 4.3 价格规则

- 接受示例：19、19.9、19.90、0.01。
- 使用半角数字，整数部分至少一位；如有小数点，其后必须有一到两位数字。不接受 .9、19.、+19 或全角数字。
- 建议允许范围：0.01～999999.99 元。
- 不接受 0、负数、空值、文字、科学计数法、千位逗号、货币符号或超过两位小数的金额。
- 不自动四舍五入超出两位小数的输入，不把错误金额显示为 0。
- 海报统一展示为“¥19.90”的格式，始终保留两位小数。
- 本版不计算优惠、折扣或其他金额。

### 4.4 名称和特殊文字

- 36 个字符按 Unicode 码点计数，中英文、数字、标点均计入；某些组合表情可能占多个字符。
- 最多显示两行；如果按模板字体实际测量仍无法完整显示，则该商品提示名称过长，要求用户缩短后重新生成。
- 不使用省略号隐藏商品名称，不隐藏关键规格。
- 粘贴内容按普通文本处理，即使包含 HTML 标签也不作为页面代码执行。
- 系统字体无法正常显示的特殊符号，需要用户根据预览改为常用文字；第一版不引入额外字体包。

## 5. 商品图片与统一二维码

### 5.1 商品图片

- 提供一个支持多选的文件选择入口。
- 第一版仅支持静态 JPG／JPEG、PNG、WebP；GIF、SVG、HEIC 和其他格式提示不支持。
- 检查文件实际能否解码，不能只根据扩展名判定成功。
- 按文件名精确匹配，包含扩展名，区分大小写。例如 apple.jpg 不匹配 Apple.jpg。
- 不按上传顺序或商品名称猜测对应关系。
- 所选文件中有相同完整文件名时，提示冲突；不自动选择其中一张。
- 所选图片未被任何商品引用时，列出提示，可以继续生成和导出；无效文件及同名文件冲突仍需处理。
- 重新选择商品图片时，新的一组文件整体替换旧选择，不做隐式追加；界面明确说明“重新选择会替换本批商品图片”。
- 取消文件选择对话框时保留旧选择。
- 图片解码失败时保留资料和错误文件名，提示重新选择正确图片。
- 不提供文件夹上传、图片重命名、裁剪或旋转编辑。

### 5.2 图片展示

- 主图保持原始比例，完整展示在固定图片区域内。
- 不拉伸、不裁切；比例不一致时用浅色背景填充剩余区域。
- 横图、方图、竖图和透明背景图片均遵守同一规则。
- 按图片自身方向信息正确显示照片，避免手机拍摄图片方向错误。
- 替换图片或资料后，旧预览失效，必须重新生成。

### 5.3 统一二维码

- 一次只选择一个二维码文件，格式和解码要求与商品图片相同。
- 二维码为必填项，缺失或损坏时不能导出。
- 本批次所有商品使用同一张二维码图片。
- 完整、等比显示二维码，四周保留白色空间；不裁边、拉伸或用圆角遮住码图。
- 工具不解码二维码、不判断其指向内容或有效期；用户负责提供正确二维码。
- 界面提示：“本批海报共用此二维码，请确认并测试识别。”
- 重新选择二维码后，旧预览失效。

### 5.4 建议的初版资源上限

| 项目 | 示例默认值 | 超出时的处理 |
|---|---|---|
| 每批商品数 | 20 个 | 拒绝生成，提示拆成多批；不截取前 20 个 |
| 商品图片选择数量 | 20 张 | 拒绝生成，提示减少图片 |
| 单张文件大小 | 10 MB，包含二维码 | 指出文件名，提示压缩或换图 |
| 本批所选文件总大小 | 100 MB，包含二维码和未引用图片 | 提示减少或压缩文件 |
| 单张解码后的像素数 | 1200 万像素，包含二维码 | 提示缩小尺寸后重试 |

以上是控制首版复杂度和浏览器内存使用的建议边界，不代表已实测容量；正式验收需要在目标电脑上确认。大文件先检查体积，图片解码后再检查像素数；文件足够小也可能含有很大的图片尺寸。

## 6. 海报模板

### 6.1 固定规格

- 导出格式：PNG。
- 画布尺寸：720 × 1280 像素。
- 背景：白色。
- 正文：深灰色；价格：红色。
- 字体：浏览器可用的常见系统中文字体。
- 预览与导出采用同一份绘制规则，预览只做等比缩放。

### 6.2 固定内容与顺序

| 区域 | 内容 | 展示要求 |
|---|---|---|
| 顶部 | 商品名称 | 最多两行，完整显示 |
| 中部 | 商品主图 | 完整、等比展示，作为主要视觉内容 |
| 下部 | 团购价 | 大字号，显示人民币符号和两位小数 |
| 底部 | 统一二维码 | 白色留边，完整显示 |

建议初始版式：画布左右留白各 36 像素；标题区域高 120 像素；主图区域为 648 × 600 像素；价格区域高 110 像素；底部二维码白底框约 228 × 228 像素。开发时可调整间距以保证四个区域互不重叠，但不增加可编辑项或改变海报尺寸。

不添加样例商品信息、默认价格、模板水印、广告或未填写的占位文案。缺少必填资料的商品只展示错误状态，不生成带占位内容的成品图。

## 7. 页面结构与交互

单页从上到下排列，不增加导航、设置页或多个步骤页面。

| 区域 | 内容 |
|---|---|
| 说明区 | 工具名称、一句话用途、刷新后资料不保留的提醒 |
| 资料区 | 三列格式说明、示例表、可粘贴的文本框 |
| 图片区 | 商品图片多选入口、所选数量、统一二维码入口与小预览 |
| 操作区 | “生成预览”与“下载全部海报 ZIP”两个主要按钮 |
| 检查区 | 商品总数、问题数量、对应行号或文件名、修正方法 |
| 预览区 | 按商品行顺序展示海报缩略图，可放大查看单张 |

### 7.1 按钮规则

- 初始状态可点击“生成预览”；缺少资料时给出可理解的提示。
- 没有生成预览，或本批次存在阻止导出的错误时，下载按钮不可用，并在附近说明原因。
- 有效商品可显示预览，有问题的商品显示错误卡片；整批全部有效后才允许导出。
- 修改粘贴文本、重新选择主图或二维码后，旧海报预览立即失效，下载按钮不可用；提示“资料已变化，请重新生成预览”。
- 生成或导出期间禁用重复操作和输入修改，显示当前处理进度；结束或失败后恢复可操作状态。
- 没有问题的预览生成后，不因放大查看而改变商品资料。
- 没有独立商品编辑器；用户通过修改粘贴文本或重新选择文件修正资料。

### 7.2 基本可访问性

- 输入框、文件选择、按钮和放大预览入口有明确标签，可通过键盘操作。
- 错误同时使用文字说明，不仅依赖红色标记。
- 状态和进度可被辅助技术读取。
- 放大预览可通过关闭按钮或 Escape 关闭，关闭后焦点回到原入口。

## 8. 导出规则

### 8.1 文件内容与命名

- 一行商品资料导出一张 PNG，即使两个商品名称相同，也不覆盖。
- PNG 命名格式：三位序号-商品名称.png，例如 001-冰糖心苹果 5斤装.png。
- 序号从 001 开始，按有效商品资料行顺序排列；表头和空行不占序号。
- 文件名中的路径分隔符、控制字符及常见系统不允许的字符替换为下划线；清理后为空时使用“商品”。原商品名称仍按原文展示在海报中。
- ZIP 命名格式：快团团素材-YYYYMMDD-HHmmss.zip，时间按 Asia/Shanghai 生成。
- ZIP 中只包含本批次的 PNG，不放入原始图片、二维码文件、资料表或额外清单。

### 8.2 完成、进度和失败

- 显示“正在导出 3／10”和“正在打包”等真实进度，不伪造百分比。
- 所有 PNG 和 ZIP 成功生成后，才触发一次浏览器下载。
- 任一商品渲染或打包失败时，不下载缺少商品的部分 ZIP，不显示全部成功；列出失败商品或打包错误。
- 失败后保留本批资料、文件选择和可用预览；允许再次点击下载，重新导出整批。
- 文件输出成功后恢复按钮，可再次下载同一批海报。
- 成功提示为“已生成 10 张海报并发起 ZIP 下载，请检查浏览器下载记录”；不能声称文件已保存到用户磁盘，因为保存可能被取消或被浏览器拦截。
- 用户取消保存或浏览器限制下载时，资料仍保留；允许重新发起下载，不要求重新录入。

## 9. 异常处理示例

| 情况 | 提示示例 | 能否导出 |
|---|---|---|
| 空文本或只有表头 | 请粘贴至少一条商品资料 | 否 |
| 第 4 行只有两列 | 第 4 行缺少列，请按商品名称、团购价、图片文件名填写三列 | 否 |
| 某一行超过三列 | 第 3 行有 4 列，请只复制指定的三列 | 否 |
| 名称为空 | 第 2 行商品名称为空 | 否 |
| 名称超过限制或放不下 | 第 2 行商品名称过长，请缩短后重新生成 | 否 |
| 价格填成 ¥19.9 | 第 2 行团购价格式错误，请填写纯数字，如 19.90 | 否 |
| 未找到主图 | 第 5 行未找到 milk.png，请检查文件名或重新选择图片 | 否 |
| 多个文件同名 | 所选图片中有多个 apple.jpg，请重命名冲突文件并更新资料 | 否 |
| 主图无法解码 | apple.jpg 无法读取，请换一张 JPG、PNG 或 WebP 图片 | 否 |
| 未引用的图片 | extra.jpg 未被商品引用，将不参与导出 | 是，其他检查通过时 |
| 未选择二维码 | 请先选择统一二维码 | 否 |
| 超过商品数上限 | 本批有 21 个商品，请拆成每批最多 20 个 | 否 |
| 修改了已预览资料 | 资料已变化，请重新生成预览 | 否，重新生成后再判断 |
| 第 6 个商品导出失败 | 第 6 个商品导出失败，本次未生成下载文件，请重试 | 否，本次不下载部分结果 |
| ZIP 打包失败 | 打包失败，资料已保留，请重新点击下载 | 否，本次不显示成功 |

所有错误都应能定位到具体行、具体文件或具体操作。禁止只显示“出错了”，也禁止无提示跳过失败行。

## 10. 数据处理与实现边界

本节用于让开发者理解最小实现边界，不要求产品用户选择技术方案。

- 使用浏览器本地处理：文本解析、图片读取、海报绘制和 ZIP 打包均在本机完成，不需要业务后端或数据库。
- 不发送商品资料、主图或二维码到服务器；不接入统计或上传接口。
- 使用浏览器标准能力解析粘贴文本和绘制海报；ZIP 打包可采用一个适合浏览器的库，不为 Excel 解析引入依赖。
- 若需要 ZIP 依赖，随产品提供，避免运行时从第三方 CDN 加载；静态工具如何交付在实施方案中明确，公开部署另行授权。
- 数据只保留在当前页面内存中，不使用 localStorage、IndexedDB 或云端保存草稿。
- 页面刷新、关闭或崩溃后，资料不保留；页面常驻显示此提醒。用户的原始文件不受影响。
- 处理时以生成预览时的有效资料为准；修改使预览失效，避免预览内容与导出内容不一致。
- 按商品顺序处理海报，及时释放可释放的中间图像资源，不同时生成无上限数量的画布。
- 出错时恢复界面操作，不清空用户资料。
- 不把用户输入当作 HTML、脚本、文件路径或远程 URL 执行；所需图片均来自用户明确选择的本地文件。
- 初版支持目标为电脑端稳定版 Chrome／Edge；移动端、微信内置浏览器及其他浏览器不作为本版验收对象。
- 页面支持普通笔记本屏幕和浏览器缩放；控件不得相互遮挡，预览保持海报比例。
